# 健康度指标

最终版不再是一次性 Pilot 验收，而是**持续观测**——定期看这些指标，决定知识库是在健康生长还是在腐烂。

建议每月（配合一次 `/lint deep`）检查一次。

---

## 核心指标（必看）

### M1 · 可引用率

```
可引用率 = mature 页面数 / 总 concept 页面数
```

**目标**：稳态 ≥ 40%

**解读**：
- < 20%：知识库还在萌芽期，继续投喂
- 20-40%：生长期，检查有没有 bud 堆积
- ≥ 40%：稳态，wiki 开始成为你的可信来源

### M2 · 花苞绽放率

```
花苞绽放率 = 过去 30 天内从 bud 升级的页面数 / 30 天前的 bud 总数
```

**目标**：≥ 30%/月

**解读**：
- < 10%：大量花苞被遗忘，说明 Digest 和 Lint 没有驱动行为——检查你是不是真的在看这两个文件
- 10-30%：正常节奏，部分花苞在自然生长
- ≥ 30%：健康——你确实在根据 Lint 的提示补充素材

### M3 · Synthesis 页面占比

```
synthesis 占比 = synthesis 页面数 / 总 wiki 页面数
```

**目标**：5-15%

**解读**：
- < 3%：你在用 `/query ephemeral` 或选 [3]——洞察没有沉淀，是在泄漏价值
- 5-15%：健康，问答产物在复利
- > 25%：synthesis 生成过度频繁——可能每个小问题都在归档，考虑更严格的节制

### M4 · Digest 消费率

```
Digest 消费率 = 打开过的 latest.md 次数 / ingest 命令次数
```

**目标**：≥ 80%

**解读**：
这是自问自答指标——如果你每次 ingest 都没去看 Digest，说明：
- 你没养成习惯
- Digest 写得不够有价值（调整 CLAUDE.md §9）
- 你在用命令却不在用知识库

### M5 · Lint 真阳性率

```
Lint 真阳性率 = 值得处理的发现数 / Lint 报告的总发现数
```

每次 `/lint deep` 后评估。

**目标**：standard ≥ 60%；deep ≥ 40%

**解读**：
- 太低（<30%）：阈值设得太松，噪音多，调整 CLAUDE.md §10.2
- 合适：你在处理 Lint 的建议
- 太高（>80%）：阈值设得太严，可能漏掉问题，适当放松

## 辅助指标（可选看）

### M6 · Cluster 分布均匀度

查看 `/lint` 报告的 Cluster 统计表。**目标**：单一 cluster 页面占比 < 40%。

若某个 cluster 占比 > 60%，说明你的素材过于集中。要么扩展 cluster（把大类拆成几个），要么接受「这就是我的研究方向」。

### M7 · 孤岛率

```
孤岛率 = 孤岛页面数 / 总 concept 页面数
```

**目标**：< 10%

孤岛多意味着交叉链接没建好。运行 `/lint` 后人工在相关页面补充反向引用，或通过 `/query` 触发综合来建立连接。

### M8 · `_log.md` 活跃度

```bash
grep "^## \[$(date +%Y-%m)" _log.md | wc -l
```

本月的命令执行数。**目标**：≥ 15/月（平均每两天一次）。

低于 5/月 → 系统被冷落了，考虑提醒自己每日投喂。

### M9 · 矛盾处理速度

每次 `/lint deep` 报告的「疑似矛盾」数。

**目标**：每月下降或保持为零。矛盾堆积说明你在看到矛盾提示后没有行动。处理方式：
- 在两个页面中加入「观点分歧」section
- 或者判断哪一方正确，在另一方加注「已被 X 修正」

## 失败信号（立即行动）

这些情况出现时，需要检查系统配置或自己的习惯：

| 信号 | 含义 | 行动 |
|------|------|------|
| 连续 2 周未投喂 | 习惯中断 | 找一篇素材立刻 `/ingest` |
| 花苞绽放率 < 10% 连续 2 月 | Lint 没在驱动行为 | 把 `_lint/latest-report.md` 设为 Obsidian 启动页 |
| synthesis 占比 < 3% 连续 2 月 | 洞察在泄漏 | 强制使用 `/query save` 两周 |
| mature 页面反复被修改 | 来源冲突没处理 | `/lint deep` 查矛盾 |
| Lint deep 假阳性 > 70% | 启发式阈值不对 | 调整 CLAUDE.md §10 |
| 生成内容频繁不合规则 | CLAUDE.md 规则漂移或冲突 | 重读 CLAUDE.md §5 红线，补强对应命令文件的 reference |

## 每月体检流程

```
1. /lint deep
2. 打开 _lint/latest-report.md 通读
3. 统计本文指标：
   - grep -c "^## \[$(date +%Y-%m)" _log.md      # M8
   - 手动点算 mature / total concept              # M1
   - 手动点算 synthesis 数                         # M3
4. 记录在自己的月度日志中（或者投喂给 wiki 自己）
5. 对 M1/M2/M3 中不达标的项，本月采取对应行动
```

---

## 指标不是目的

这些指标是**看护仪表盘**，不是 KPI。知识库的价值在于你真的会用它——在工作汇报前查一次、在做决策前问一次、在读新文章时看看相关页面有没有。

如果你发现自己在「为了好看的指标」做事而不是「因为真有用」投喂，那就退一步。先恢复日常使用，再谈数字。
